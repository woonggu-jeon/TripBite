## 1. 비주얼 테마 & 분위기

**한 줄 요약: 하얗고 널찍한 화면 위에, 선명한 초록 하나로 다음 행동을 가리킨다.**

- **밝고 가벼움.** 배경은 순백(`#FFFFFF`)이 기본. 회색 톤 배경은 섹션 구분(`#F6F6F6`)에만
  아주 제한적으로 쓴다. Light가 이 브랜드의 기본값이고, 다크 모드는 같은 위계를
  어두운 중성색으로 옮긴 것일 뿐 별도의 톤이 아니다(§2 Dark 열).
- **음식 은유의 여행.** 로고는 초록 잎/점 + 주황 단지(항아리) 조합이다. "한 입에 떠나는
  충북 여행"이라는 태그라인처럼, 여행을 부담 없이 한 입 크기로 잘라 권하는 톤.
  귀엽지만 유아적이지 않고, 정보는 또박또박 전달한다.
- **한 화면 = 한 행동.** 화면마다 초록 채움 버튼은 **하나만** 둔다. 나머지 액션은
  라인 버튼이나 초록 텍스트 링크로 위계를 낮춘다.
- **평평하다.** 그림자를 쓰지 않는다(§6 참조). 깊이는 그림자가 아니라 **여백과
  1px 헤어라인**으로 만든다.
- **여백이 넉넉하다.** 상태 안내 화면은 상단 60px를 비우고 시작하고, 로고 블록 아래는
  40px를 비운다. 요소를 빽빽하게 채우지 않는다.
- **게이미피케이션이 깔려 있다.** 랭킹·토너먼트·트로피·편지·타입 테스트가 제품의 축이다.
  성취 표현은 요란한 그라디언트가 아니라 파스텔 원형 배지와 계절 색으로 한다.

**밀도**: 여유로운(comfortable) 쪽. 컨트롤 높이 52px, 필드 간격 16px, 블록 간격 24px.

## 3. 타이포그래피

**폰트: Pretendard.** 한글 UI 폰트 하나로 통일한다. 영문 전용 폰트를 섞지 않는다.

핵심: **letter-spacing이 항상 음수(-2%)** 다. 한글 가독성을 위해 자간을 좁히는 것이
이 시스템의 특징이므로, 기본값(0)으로 두면 톤이 무너진다.

| 스타일                  | 크기 | 웨이트       | 행간 | 자간    | 용도                       |
| ----------------------- | ---- | ------------ | ---- | ------- | -------------------------- |
| `Title/B_24_130%`       | 24   | Bold 700     | 130% | -2%     | 화면 대제목, 결과 값       |
| `Title/B_20_130%`       | 20   | Bold 700     | 130% | -2%     | 로고 워드마크, 섹션 대제목 |
| `Title/B_18_140%`       | 18   | Bold 700     | 140% | -2%     | 헤더 타이틀                |
| `Basic Body/B_16_140%`  | 16   | Bold 700     | 140% | -2%     | 강조 본문                  |
| `Basic Body/SB_16_140%` | 16   | SemiBold 600 | 140% | -2%     | **버튼 라벨(채움)**        |
| `Basic Body/M_16_140%`  | 16   | Medium 500   | 140% | -2%     | 입력 값, 라인 버튼 라벨    |
| `Basic Body/R_16_140%`  | 16   | Regular 400  | 140% | -2%     | 본문                       |
| `Basic Body/B_14_140%`  | 14   | Bold 700     | 140% | -2%     | 초록 텍스트 링크           |
| `Basic Body/SB_14_140%` | 14   | SemiBold 600 | 140% | -2%     | 소제목                     |
| `Basic Body/M_14_140%`  | 14   | Medium 500   | 140% | -2%     | 목록 항목                  |
| `Basic Body/R_14_140%`  | 14   | Regular 400  | 140% | -2%     | 설명문                     |
| `Caption/R_12`          | 12   | Regular 400  | 140% | **-1%** | 입력 라벨, 메타            |
| `Caption/B_10`          | 10   | Bold 700     | 120% | -2%     | 배지                       |
| `Caption/M_10`          | 10   | Medium 500   | 120% | -2%     | 입력 헬퍼/에러 캡션        |

- 제목(20·24)만 행간 130%, 나머지는 140%, 10px 캡션은 120%.
- `Caption/R_12`만 자간 -1%다. 다른 값들과 다르니 그대로 지킬 것.
- 굵기는 400/500/600/700 네 단계만 쓴다. 300, 800, 900을 새로 만들지 않는다.

## 4. 컴포넌트 스타일

### 버튼

변형 축: `size` (52px / 36px) × `style` (solid / line / icon) × `color` (Green / Gray / Accent)
× `state` (default / disabled). 모양은 `square`(=라운드 사각) 하나뿐 — **알약(pill) 버튼은 없다.**

| 변형             | 면        | 테두리        | 라벨               |
| ---------------- | --------- | ------------- | ------------------ |
| solid / Green    | `#00B334` | 없음          | `SB_16`, `#FFFFFF` |
| line / Green     | `#FFFFFF` | 1px `#00B334` | `M_16`, `#00B334`  |
| solid / disabled | `#E0E0E0` | 없음          | `SB_16`, `#B4B4B4` |
| line / disabled  | `#FFFFFF` | 1px `#E0E0E0` | `M_16`, `#B4B4B4`  |

- 높이 52px(주), 36px(보조). 패딩 `16px 20px`. 라운드 **12px**.
- 전체 폭 버튼은 화면 좌우 20px 여백을 뺀 320px.
- 입력 옆에 붙는 보조 버튼은 폭 80px 고정.

### 입력 필드 (`inputField`)

`라벨(Caption/R_12) → 입력 박스(52px) → 헬퍼 캡션(Caption/M_10)` 3단 구성, 간격 4px.
상태: `default` / `active` / `error` / `done`.

| 상태              | 테두리    | 캡션 색   |
| ----------------- | --------- | --------- |
| default           | `#E0E0E0` | `#151515` |
| active(값 입력됨) | `#B4B4B4` | `#151515` |
| error             | `#F73737` | `#E1493C` |
| done              | `#E0E0E0` | —         |

- 라운드 12px, 패딩 `12px 16px`, 값 텍스트 `M_16`.
- 비밀번호 필드는 우측에 20px 눈 아이콘 토글(`eyeIcon` on/off).
- 헬퍼 캡션에 **입력 규칙을 항상 노출한다** (예: `영문or숫자/특문제외/4자 ~ 20자`).
  규칙을 숨기고 에러로만 알려주는 방식은 이 시스템의 패턴이 아니다.
- 중복확인처럼 검증이 필요한 필드는 우측 80px 버튼을 두고,
  통과하면 라벨을 `확인완료`로 바꾸고 비활성 채움으로 잠근다.

### 헤더

높이 **56px**, 좌우 패딩 20px. 좌측 24px 아이콘, 타이틀은 `Title/B_18` 중앙 정렬.
`type`: `default` / `sub` / `noti` / `find` / `location` / `my`.

- 폼 화면(`sub`)은 하단 1px `#E0E0E0` 헤어라인 있음.
- 상태 안내 화면(`find`)은 헤어라인 없고 타이틀도 없이 뒤로가기만 둔다.

### 원형 아이콘 배지 (`circle`)

크기 72 / 84 / 96px. 면은 연한 초록(`#EAF6EF`), 내부 아이콘은 `#00B334` 스트로크.
아이콘: `check` `letter` `lock` `location` `noti` `trophy` `heart`.
84px일 때 내부 아이콘 36px.

### 상태 안내 블록 (`authItme` / `emptyItme`)

제품 전체에서 쓰는 빈 상태·완료·안내 패턴.

```
[원형 배지 84px]          ← 중앙
   ↕ 10px
제목  Title/B_24, #151515  ← 중앙
   ↕ 12px
설명  R_14, #393939, 2줄   ← 중앙
```

설명문은 2줄로 끊어 쓴다. 한 줄로 길게 늘이지 않는다.

### 하단 내비게이션 (`nav`)

5탭 고정: **홈 / 랭킹 / 토너먼트 / 편지 / 마이.** 아이콘 `navIcon`이 on/off 두 상태를
가지며, 활성 탭만 `#00B334`.

### 카드류

`DestinationCard` (여행지, 설명 유무 3변형) · `heroCard` · `visualCard`(rank/match) ·
`progCard`(진행도 on/off) · `letterItem`/`letterBox`(편지, 페이지네이션 유무) ·
`typeTestItem` · `typeTextResultItem`.
공통: 라운드 12px, 그림자 없음, 면색은 흰색 또는 계절/연초록 파스텔.

### 그 외

`chip-on`(on/off) · `toggle`(on/off) · `checkbox`(20px, line, on/off) ·
`wideTabMenu`(get/send/save) · `modal`(기본/nickName/pw) · `bottomModalIcon`(camera/photo/profile) ·
`seasonIcon`(36/64px × 4계절) · `tripTypeIcon`(36/52px × taste/challenge/explore/rest) ·
`themeIcon`(dice/season) · `notiCircle`(44px, letter/master, on/off) · `IC-right` · `detailIcon`.

## 5. 레이아웃 원칙

- **기준 아트보드 360 × 720** (모바일 세로). 이 폭을 기준으로 모든 값이 정해져 있다.
- **화면 좌우 여백 20px.** 전체 폭 요소는 320px.
  일부 중앙 정렬 블록만 24px 여백(=312px)을 쓴다.
- 4pt 그리드를 엄격히 지키지는 않는다. 실제 쓰이는 값:
  `2 · 4 · 8 · 10 · 12 · 16 · 20 · 22 · 24 · 26 · 28 · 30 · 36 · 40 · 60`
- 주요 리듬:
  | 관계 | 간격 |
  | --- | --- |
  | 라벨 ↔ 입력, 입력 ↔ 헬퍼 | 4px |
  | 입력 필드끼리 | 16px |
  | 블록(필드묶음 / 버튼 / 링크) | 24px |
  | 상태 안내 블록 ↔ 폼 | 36px |
  | 안내 화면 상단 여백 | 60px |
- 하단 고정 CTA는 화면 아래에서 28~40px 띄운다.
- 세로로 짧은 콘텐츠는 위로 붙이지 않고 **수직 중앙 정렬**한다(완료/빈 상태 화면).

## 6. 깊이 & 엘리베이션

**이 시스템에는 그림자가 없다.** Figma 파일의 이펙트 스타일이 0개이고, 시안 어디에도
드롭섀도가 쓰이지 않았다.

깊이는 이렇게 만든다:

1. **1px `#E0E0E0` 헤어라인** — 헤더 하단, 입력 테두리
2. **연한 면색** — `#EAF6EF`(초록), `#F6F6F6`(섹션), 계절 파스텔
3. **여백**

> 에이전트 주의: 카드나 모달에 `box-shadow`를 임의로 넣지 말 것. 떠 있는 느낌이 꼭
> 필요한 바텀시트/모달에만 최소한으로 쓰고, 그 외에는 테두리와 면색으로 해결한다.

## 7. Do & Don't

**Do**

- 화면당 초록 채움 버튼 하나. 나머지는 라인 버튼 또는 초록 볼드 텍스트 링크.
- 라운드는 12px로 통일.
- 입력 규칙·제약을 헬퍼 캡션으로 미리 보여준다.
- 상태(완료/빈/에러)는 `원형 배지 + 24px 볼드 제목 + 14px 2줄 설명` 패턴으로.
- 한글 텍스트에 자간 -2%(캡션 12px은 -1%)를 적용한다.
- 계절/여행타입은 전용 아이콘 세트와 파스텔 면색으로 구분한다.

**Don't**

- 그림자 남발, 글래스모피즘, 그라디언트 — 전부 이 브랜드가 아니다.
- 주황(`#F79D26`)을 주 CTA 색으로 쓰기. 주황은 로고와 포인트 전용.
- 계절 파스텔을 텍스트 색으로 쓰기 (대비 부족).
- 알약형 버튼, 20px 이상 큰 라운드.
- Pretendard 외 폰트 혼용, 300/800/900 웨이트 신설.
- 초록 채움 버튼 두 개를 나란히 두기.

## 7-1. 접근성 — 알려진 미해결 사항

**초록 채움 버튼의 흰 라벨 대비가 부족하다.** `#FFFFFF` on `#00B334` = **2.80:1**.
라벨은 16px SemiBold로 WCAG의 "큰 텍스트"(24px, 또는 18.66px Bold) 기준에 들지 않으므로
4.5:1이 필요한데 미달이다. Light/Dark 공통이다.

> **에이전트 주의: 이 값을 임의로 고치지 말 것.** 브랜드 초록과 버튼 라벨 색은 디자인
> 결정 사항이고 아직 정해지지 않았다. 시안대로 `#00B334` + 흰 라벨을 유지하고,
> 대비를 "개선"한다며 초록을 어둡게 하거나 라벨을 검게 바꾸지 말 것.
> (참고 수치 — 면을 `#00821F`까지 어둡게 하면 4.5:1 통과, 라벨을 `#151515`로 바꾸면 6.52:1 통과.)

그 외 지켜야 할 것:

- 본문 텍스트 `#151515` on `#FFFFFF` = 18.3:1, 보조 `#393939` = 11.6:1 — 충분하다.
- 약한 텍스트 `#8A8A8A` on `#FFFFFF` = 3.45:1 — 4.5:1 미달이다. **메타 정보에만** 쓰고
  본문·라벨에 쓰지 말 것.
- 초록 원형 배지의 아이콘 `#00B334` — Light(`#EAF6EF` 위) **2.53:1**, Dark(`#16301E` 위)
  5.09:1. Light는 비텍스트 3:1 기준에 미달한다. 다만 이 글리프는 바로 아래 제목·설명
  텍스트가 같은 의미를 전달하는 **장식 요소**라서 허용 범위로 본다.
  → 원형 배지 아이콘만으로 정보를 전달하는 화면을 만들지 말 것. 항상 텍스트를 곁들인다.
- 계절 파스텔(`#FFEBEB` 등)은 면색 전용. 그 위 텍스트는 `#151515`를 쓴다.
- 포커스 표시를 없애지 말 것. 키보드 포커스는 `#00B334` 2px 아웃라인 + 2px 오프셋.
- 에러는 색만으로 알리지 않는다 — 테두리 색과 **함께 캡션 텍스트**를 반드시 보여준다.

   않기로 했다. 구현체의 `0.15s ease`(배경·테두리)는 **디자인 결정이 아니다.**
   에이전트는 모션을 임의로 만들어 넣지 말 것.

   코드에도 구현되어 있으나(§2 표의 Dark 열), **실제 화면 시안은 Light만 그려져 있다.**
   즉 다크에서의 레이아웃·강조 판단은 시안 근거가 없으므로, §2 색상 매핑만 신뢰하고
   그 밖의 다크 전용 처리를 발명하지 말 것.
   단색 UI 아이콘(뒤로가기·눈)은 `mask-image` + `currentColor`로 처리해 텍스트 색 토큰을
   따라간다. 브랜드 로고와 초록 원형 아이콘은 두 모드에서 원본 색을 유지한다.
3. **입력 라운드에 10px/12px이 섞여 있다.** 라이브러리 불일치로 보고 **12px로 통일**했다.
4. **태블릿/데스크톱 시안 없음.**
5. `detailIcon` 컴포넌트 세트는 현재 Figma에서 오류 상태다(속성 정의를 읽을 수 없음).
