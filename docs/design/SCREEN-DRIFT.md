# 화면 드리프트 — Figma `페이지` ↔ 레포 라우트

> 4단계(화면 구성) 작업의 근거 문서. Figma 화면 62개와 레포 라우트 30개를 대조한다.
> 작성 시작: 2026-08-03. **진행 중 — 아래 "검토 상태"에 표시된 화면만 실제 비교됨.**

---

## 0. 읽는 방법

**드리프트 등급**

| 등급  | 뜻                                                   | 작업 성격                         |
| ----- | ---------------------------------------------------- | --------------------------------- |
| **A** | 구조가 다름 — 섹션 종류·순서·구성 요소가 어긋남      | UI 재작업 (기능·데이터 영향 가능) |
| **B** | 구조는 같고 스타일이 다름 — 탭 모양, 배너 형태, 여백 | 스타일 수정                       |
| **C** | 거의 일치 — 미세 여백/색만                           | 소소한 정리                       |
| **?** | 미검토                                               | —                                 |

### ⚠ 드리프트로 세지 않는 것 (환경 한계)

비교는 목 모드(`NEXT_PUBLIC_USE_MSW=true`, worktree `../TripBite-verify`, 포트 3902)에서
했다. 다음은 **실 API 에서는 정상이므로 드리프트가 아니다.**

1. **이미지 자리에 이모지가 보임** — `MediaThumb` 이 `src` + `emoji` fallback 구조이고
   컴포넌트들이 이미 `imageUrl` / `heroImage` / `photos` 를 소비한다. 목 시드가
   `imageUrl: null` 이고 생성 faker 목은 URL 이 아닌 임의 문자열을 주기 때문에
   항상 fallback 이 나온다. 실 API 이미지가 붙으면 사진이 표시된다.
2. **목록이 빈 상태로 나옴** — 목 데이터 부족.
3. **PWA 업데이트 배너 / dev 오버레이 / 우하단 배지** — 개발 환경 요소. 유지 결정됨.

> ⚠ **PWA 배너는 sticky 헤더를 가린다** (높이 60px, `top: 0`). 이 때문에 초판에서
> "헤더 부재" 를 오판했다 (§3 정정). 캡처 시 배너를 DOM 에서 제거할 것:
>
> ```js
> [...document.querySelectorAll('div,section,aside')]
>   .filter(
>     (e) =>
>       /새 버전이 있어요|앱처럼 빠르게/.test(e.textContent || '') &&
>       e.getBoundingClientRect().top < 80 &&
>       e.getBoundingClientRect().height < 140,
>   )
>   .forEach((e) => e.remove());
> ```

### 문구는 이 문서의 대상이 아니다

Figma 문구와 앱 문구가 달라도 **드리프트로 적지 않는다.** 문구는 나중에 일괄 정리하기로
했고, SoT 는 `src/i18n/messages/*.json` 이다 ([HANDOFF.md §0-1](./HANDOFF.md)).
단 "탭이 3개인데 이름이 다름" 처럼 **구성 요소 수·의미가 달라지는 경우는 적는다.**

## 2. 화면별 상세

### 2.1 `HOME · 홈` → `/` — 등급 A

| 항목        | Figma                                                        | 현재                                                 |
| ----------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| 히어로      | 사진 배경 카드 1장, "오늘의 여행" eyebrow + 20px 제목 + 위치 | **처리 완료** — 사진 배경 히어로 (캐러셀 유지, §3-1) |
| 섹션 2 제목 | "이런 여행 어때요?" + `더보기 >`                             | "곧 충북에서 열리는 축제"                            |
| 섹션 2 필터 | **칩 4개** (전체/관광지/축제/체험관광)                       | **없음**                                             |
| 카드        | 정사각 사진 + 제목 + 위치(핀 아이콘)                         | 카드 + D-day 배지 + 카테고리 + 제목                  |
| 진입 배너   | 초록/주황 2개, 각 원형 배지 + 2줄 + **오른쪽 "시작" 버튼**   | 유사 구조, 버튼 없음                                 |
| 헤더        | 종 · 로고 · 설정                                             | 종 · (dev 배지들) · 로고 · 설정                      |

**작업 성격** — 칩 필터는 상태·필터링 로직이 필요(기능 추가). 히어로를 캐러셀에서
단일 카드로 바꾸는 것은 컴포넌트 교체. 배너 버튼 추가는 스타일+동작.

### 2.5 `RNK · 랭킹` → `/ranking` — 등급 B

TOP5 목록 + "시군별 우승 횟수" 막대 11개 구조가 **일치**한다.

| 항목          | Figma                                  | 현재                                    |
| ------------- | -------------------------------------- | --------------------------------------- |
| 헤더          | 뒤로가기 + "여행지 랭킹"               | 오판 — 헤더 존재 (§3 정정)              |
| TOP5 1위      | 큰 사진 카드 + 이름/시군 오버레이      | 다른 항목과 같은 행 (금색 원형 순위)    |
| TOP5 2~5위    | 원형 썸네일 + 이름 + "시군 · N회 우승" | 원형 순위 배지 + 이름 + 시군 + 우측 N회 |
| TOP5 컨테이너 | 카드 하나 안에 5개 묶음                | 항목마다 개별 카드                      |
| 막대 목록     | 카드 하나 안에 11행, 행 구분선         | 행마다 개별 카드                        |

→ **1위 강조(사진 카드)** 와 **묶음 카드 vs 개별 카드** 가 핵심 차이.

### 2.6 `RGN · 시군상세` → `/region/[code]` — 등급 B

히어로 + 칩 필터 4개(전체/관광지/축제/체험관광) + 카드 그리드 구조가 **일치**한다.
홈에는 없던 칩 필터가 이 화면에는 이미 있다.

| 항목        | Figma                                                  | 현재 (개선 후)                   |
| ----------- | ------------------------------------------------------ | -------------------------------- |
| 히어로      | 단색 #EAF6EF 면, 320x103, 썸네일 없음 (사진 배경 아님) | 동일 — `--color-primary-soft` 면 |
| 카드 그리드 | 2열, 사진 + 제목 + 위치                                | 2열, 이미지 + 시군 + 제목 + 설명 |

> **정정** — 이 표의 이전 판은 히어로를 "사진 배경 + 시군명 오버레이" 로 적었으나
> **오판이었다.** Plugin API 로 `3413:7074` 를 열어보니 화면 전체에 IMAGE fill 이
> 하나도 없고, `banner` 프레임은 단색 `#EAF6EF` + 1px `#E0E0E0` 보더이며 텍스트도
> 흰색이 아니라 `#151515`/`#393939` 다. 사진 배경 히어로는 **홈과 랭킹 1위뿐**이다.
> 스크린샷만 보고 세 화면을 묶어 판단한 것이 원인 — 코드/노드 데이터로 확인해야 한다.

### 2.7 `TST · 유형테스트 질문` → `/quiz` — 등급 C

### ❌ 정정 — "헤더 부재" 는 오판이었다 (2026-08-03)

초판에 "Figma 는 하위 화면마다 헤더가 있는데 레포는 `/letter` 외에 없다" 고 적었으나
**사실이 아니다.** `SubHeader` 는 이미 거의 모든 라우트에서 쓰이고 있고, DOM 실측 결과
헤더가 정상 렌더된다.

| 라우트           | `h1` 실측                 | 위치     |
| ---------------- | ------------------------- | -------- |
| `/ranking`       | "여행지 랭킹"             | top=15px |

**오판 원인** — 캡처에 PWA 업데이트 배너(높이 60px, `top: 0`)가 sticky 헤더를 덮었다.
배너는 유지 결정된 개발 환경 요소이므로, 이후 캡처는 배너를 제거하고 한다.

→ 각 화면 상세표의 헤더 관련 항목도 모두 무효로 표시했다. 실제 헤더 관련 드리프트는
**`/mypage` 한 곳뿐**이다 (Figma 는 `뒤로가기 + "마이페이지" + 톱니`).

1. **묶음 카드 vs 개별 카드** — Figma 는 목록을 카드 하나 안에 넣고 행 구분선으로 나누는데

2. **섹션 헤더의 `전체 보기 >`** — Figma 는 섹션 제목 우측에 더보기 링크가 있다.
   홈 · 마이페이지에서 반복.

### 3-1. 히어로 — 처리 완료

Figma Plugin API 실측 결과 사진 배경 히어로는 **2곳**이다 (시군상세는 아니다).

| 위치     | Figma 노드          | 스펙                                                           |
| -------- | ------------------- | -------------------------------------------------------------- |
| 홈       | `hero-block > hero` | 320x176, radius 12, 텍스트 세로 중앙, eyebrow + 제목 + 핀/위치 |
| 랭킹 1위 | `visualCard > hero` | 288x176, radius 12, 텍스트 하단 좌측, 제목 + 시군/횟수         |
| 시군상세 | `banner`            | 320x103, **사진 아님** — 단색 `#EAF6EF` + 보더, 어두운 텍스트  |

공통 레이어 구조 (`components/ui/HeroCard`):

- `hero-img` — IMAGE(FILL) = `object-fit: cover`, 없으면 `#A8B29C` 플레이스홀더
  (`--color-media-placeholder`) + emoji
- `hero-overlay` — `gradientTransform` 항등행렬 = **좌→우** 축.
  `rgba(0,0,0,.72) 0% → .40 40% → 0 72% → 0 100%`
- `hero-text` — gap 4, 전부 `#FFFFFF`.
  `Caption/B_10` → `Title/B_20_130%` → `Caption/R_12`

Figma 에서 벗어난 3가지 (사유 포함):

1. **좌 padding 18 → 16** — 홈 인스턴스만 18px 로 그리드에서 벗어나 있었다.
   같은 컴포넌트의 랭킹 인스턴스가 쓰는 16px(`--space-4`) 로 통일. (4px 그리드 규칙)
2. **텍스트 블록 폭 78% → 62%** — 시안은 텍스트가 250/320 = 78% 까지 가는데
   scrim 은 72% 에서 이미 알파 0 이다. 시안 사진이 우측에서 중간톤이라 안 드러난
   문제로, 임의 사진에서는 흰 글씨가 흰 하늘 위에 놓인다.
3. **`text-shadow` 추가** (Figma 대응 없음) — 사진 위 흰 텍스트는 배경이 임의
   이미지라 대비 수치를 확정할 수 없다. 검정 윤곽을 얹어 순백 배경에서도 글자
   형태가 남게 한다. 스크림만으로는 우측 구간을 지킬 수 없다.

`aspect-ratio` 함정 하나 — 폭이 indefinite 한 컨테이너 안에서는 브라우저가
**min-content 높이 x 비율**로 폭을 역산한다. 실제로 홈에서 357 x 20/11 = 649px 로
부풀어 트랙을 넘겼다. 부모 grid item 에 `min-width: 0` 을 걸어 해결
(`layout.module.scss` 의 `minmax(0, 1fr)` 과 같은 취지).
